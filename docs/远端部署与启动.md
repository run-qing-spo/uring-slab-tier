# 远端部署与启动

littlecarrot 实验机上"打过补丁的 vLLM + uring_slab_tier"如何部署与启动。
搭建于 2026-08-01。机器规格见 `物理机器.md`。

## 1. 架构:源码归 git,编译产物留在机器

vLLM 是"Python 前台 + CUDA 后台":`.py` 是编排层,真正算数的是编译好的
CUDA kernel(`_C_stable_libtorch.abi3.so` 等 15 个 `.so`,约 1.3 GiB,绑死
Linux + CUDA 12.9 + sm89)。因此:

- **源码层**(所有 `.py` + `csrc`)由 git 管,本地与远端一致;
- **二进制层**(vLLM 的 1.3 GiB `.so` + `uring_slab_tier` 的 io_uring `.so`)
  不进 git,只在远端存在 —— vLLM 的直接复用 venv wheel 里编好的,
  `uring_slab_tier` 的在远端编一次。

mac 无法运行也无法编译这些二进制(无 NVIDIA GPU、无 io_uring),所以 mac 是
"改代码的机器",littlecarrot 是"唯一能跑的机器"。

## 2. 路径与仓库映射

| 本地(mac) | 远端(littlecarrot) |
|---|---|
| `/Users/macbook/vllm-0.24.0`(vLLM fork,分支 main) | `~/uring-slab-experiments/repos/vllm-0.24.0` |
| `/Users/macbook/uring-slab-tier`(origin = GitHub `run-qing-spo/uring-slab-tier`) | `~/uring-slab-experiments/repos/uring-slab-tier` |
| — | venv:`~/uring-slab-experiments/venvs/vllm024-cu129-clean`(勿重配) |

远端访问:`ssh -p 9007 adminz@littlecarrot.cn`。

**部署走 mac → 远端 push,不经 GitHub。** 两个远端 repo 都设了
`receive.denyCurrentBranch=updateInstead`,`git push` 会就地更新工作树。
本地各配了一个名为 `littlecarrot` 的 remote:

```
ssh://adminz@littlecarrot.cn:9007/home/adminz/uring-slab-experiments/repos/<repo>
```

GitHub 的 `origin` 与 `littlecarrot` **并存**——是"加 remote,不换 remote":
`push origin` = 备份到 GitHub,`push littlecarrot` = 部署到机器。

## 3. 启动命令

必须用 `PYTHONPATH` 指向 vLLM checkout,否则加载的是 venv site-packages 里的
**原版** vLLM 而非 checkout:

```bash
PYTHONPATH=/home/adminz/uring-slab-experiments/repos/vllm-0.24.0 \
  /home/adminz/uring-slab-experiments/venvs/vllm024-cu129-clean/bin/vllm serve <参数>
```

配置里挂 secondary tier 用 `spec_module_path: uring_slab_tier.vllm_spec`。

## 4. 日常工作流

- **改 `.py`(vLLM 插桩 或 uring_slab_tier 控制面)**:本地 `commit` →
  `git push littlecarrot main`,就地生效,**不用重编**。
- **改 `csrc`(io_uring C++)**:push 之后在远端补一句
  `pip install -e repos/uring-slab-tier` 重编 `.so`。
- **别在远端手改 tracked 文件**(会让 `updateInstead` 拒绝 push)。
- **GitHub `origin`** 想同步就 `git push origin main`,和部署互不影响。

`git push` 只带**已提交**内容;未 commit 的工作区改动不会上远端。

## 5. 一次性重建(仅当远端 checkout 需重搭时)

```bash
# 5.1 远端建 repo(两个都做),设 updateInstead
git -C <repo> init -b main
git -C <repo> config receive.denyCurrentBranch updateInstead

# 5.2 本地加 remote 并首推
git remote add littlecarrot ssh://adminz@littlecarrot.cn:9007/home/adminz/uring-slab-experiments/repos/<repo>
git push littlecarrot main

# 5.3 向 vLLM checkout 注入 wheel 的编译产物(只补缺、不覆盖补丁 .py)
SITE=~/uring-slab-experiments/venvs/vllm024-cu129-clean/lib/python3.12/site-packages
V=~/uring-slab-experiments/repos/vllm-0.24.0
rsync -a --ignore-existing "$SITE/vllm/" "$V/vllm/"
git -C "$V" ls-files --others --exclude-standard >> "$V/.git/info/exclude"  # 保持 git 树干净

# 5.4 编 uring_slab_tier 的 io_uring 扩展(scikit-build-core;远端有 aliyun 镜像)
~/uring-slab-experiments/venvs/vllm024-cu129-clean/bin/pip install -e ~/uring-slab-experiments/repos/uring-slab-tier
```

验证:`PYTHONPATH=$V <venv>/bin/python -c "import vllm; from uring_slab_tier import _uring_slab_engine; import uring_slab_tier.vllm_spec"` 无报错即可。
