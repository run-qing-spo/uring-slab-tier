## littlecarrot 正式 A/B 冻结

在产生任何 candidate 性能数据之前，正式 FS/uring A/B 冻结为：

- 主指标：`load_sustained_throughput_mib_s` 持续读取吞吐量，单位 MiB/s。
- 30 个严格紧邻配对，3 个窗口，每窗口 10 pairs
- 每窗口保持 AB/BA 平衡
- effect：`log(uring / FS)`
- 95% 分层 paired-bootstrap CI 下界大于 0
- 三个窗口效果方向都为正
- practical-effect floor：10%
- workload：72 GiB/arm，4 个 warmup passes，窗口间隔 120 秒
- 正式进程 CPU affinity：`0-15`

依据：本机 FS/FS A/A 的统计噪声地板约 0.28%，最大窗口偏差 6.81%；
低于约 7% 的差异不形成主结论，10% 为窗口漂移留出余量。

持续实验中绝对吞吐会从约 6.3 GiB/s 降到约 1.5–2 GiB/s，但紧邻配对
相关系数为 0.982。因此不能用分散运行或不成对结果判断小差异。

只要改变 72 GiB/arm、warmup、窗口间隔、CPU affinity 或其他正式
workload，必须先执行匹配的新 FS/FS A/A，再重新冻结 A/B。

candidate 参数在 correctness 与 failure injection 通过后由微基准选择，
并在第一次正式 A/B 前锁定。
